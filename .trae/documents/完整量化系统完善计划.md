# 完整量化系统完善计划

## 摘要

本计划在现有微服务骨架（6 个后端服务 + Vue 前端 + Docker 编排 + common 公共模块）基础上，按优先级补齐核心缺口，使系统达到"生产可用的完整量化投资系统"状态。采用合理默认决策：双模式数据源（mock 默认 + Tushare 可选）、JWT 多用户认证、一次性全量完善（按依赖关系排序执行）。

## 当前状态分析

### 已具备的基础
- **后端骨架完备**：6 个 FastAPI 服务均可启动，路由已注册，common 模块提供配置/DB/Redis/日志/异常/中间件/健康检查/auth 工具
- **数据层**：data-service 有 mock + tushare provider，市场路由（quote/kline/stocks/calendar）已实现
- **策略层**：strategy-engine 有完整 StrategyManager + 3 个示例策略（dual_ma/rsi_mean_reversion/macd）+ 因子工厂
- **回测层**：backtest-service 有 17KB 的 BacktestEngine + 任务后台执行 + 结果持久化模型
- **交易/风控**：trading/risk 各有 15-17KB 的 engine 模块，订单/限额/检查/VaR 等核心逻辑已实现
- **基础设施**：Docker Compose + Nginx 路由 + MySQL/Redis

### 核心缺口
| # | 缺口 | 影响 |
|---|------|------|
| 1 | portfolio-service 仅有 744 字节桩路由，无 engine.py | 组合服务实际不可用，返回硬编码假数据 |
| 2 | 服务间无集成调用 | 回测用 numpy 随机数据，交易不调风控，策略引擎不拉数据 |
| 3 | 前端 5 个 Vue 页面各约 1KB，仅表单无展示 | 无完整 UI：缺布局/导航/图表/错误处理/登录页 |
| 4 | common/auth.py 已存在但无服务接入 | 无认证，所有 API 公开 |
| 5 | trading/risk engine 全内存状态 | 重启即丢失，无法多实例 |
| 6 | 无定时任务（APScheduler/Celery） | 无数据抓取/策略定时执行/风控监控 |
| 7 | 无 WebSocket 实时推送 | 前端只能轮询 |
| 8 | 仅 test_strategy_api.py | 测试覆盖率低 |
| 9 | 回测 `execute_backtest_task` 的 TODO：market_data 用 numpy 随机生成 | 回测结果无意义 |
| 10 | /metrics 仅返回 dict，未接 Prometheus | 无监控 |
| 11 | 无 DB 迁移系统（仅 Base.metadata.create_all） | 表结构演进困难 |
| 12 | common/models 中各模型独立声明 `Base = declarative_base()` | 多服务建表时表不统一 |

---

## 设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 数据源 | 双模式：默认 mock，配置 Tushare token 后切换 | 已部分实现，无需真实凭据即可运行 |
| 交易接入 | 模拟撮合为主，预留实盘 broker 接口（占位） | README 已声明此双模式 |
| 认证 | JWT 多用户，复用 common/auth.py | 生产级形态 |
| 任务调度 | APScheduler（轻量、嵌入 FastAPI） | 无需额外 Celery/RMQ 基础设施 |
| 实时推送 | FastAPI WebSocket + Redis pubsub | 复用现有 Redis |
| 监控 | prometheus-fastapi-instrumentator | 业界标准 |
| 迁移 | Alembic | SQLAlchemy 标配 |
| 模型 Base 统一 | 统一使用 common.database.Base | 修复多 Base 问题 |

### 阶段 A：后端核心补齐（基础先行）

#### A1. 修复 common 模型 Base 统一问题
**文件**：`services/common/models/{strategy,backtest,order,portfolio,risk,market}.py`
**变更**：每个文件当前独立声明 `Base = declarative_base()`，改为从 `common.database` 导入统一 `Base`，确保所有表能一次性被 `Base.metadata.create_all` 创建。

#### A2. 补齐 portfolio-service 引擎
**新增文件**：`services/portfolio-service/app/engine.py`（参考 trading-service 的 engine 结构）
**职责**：
- `PortfolioEngine` 单例类：持仓计算、资金账户、盈亏归因、组合分析
- 接入 common/models/portfolio.py（Position/Account/AccountLog）持久化

- 暴露方法：`get_positions()`、`get_account_summary()`、`rebuild_from_trades()`、`calc_attribution()`
**重写文件**：`services/portfolio-service/app/routers/portfolio.py`

**更新 main.py**：注册路由前缀 `/portfolio` + `/api/v1/portfolio`

#### A3. 修复回测数据来源
**文件**：`services/backtest-service/app/routers/backtest.py` 第 360-382 行（`execute_backtest_task` 中的 TODO）
**变更**：删除 numpy 随机数据生成逻辑，改为通过 HTTP 调用 data-service 获取真实 K 线：
```python
# 通过 httpx 异步调用 data-service
async with httpx.AsyncClient() as client:
    for code in code_list:
        resp = await client.get(
            f"http://data-service:8006/api/v1/market/kline/{code}",
            params={"start_date": start_date, "end_date": end_date, "provider": "mock"}
        )
        # 转 DataFrame 拼装
```
**依赖**：backtest-service/requirements.txt 增加 `httpx==0.26.0`

#### A4. 服务间集成
**a) strategy-engine 接入 data-service**：
- 新增 `services/strategy-engine/app/data_client.py`：异步 HTTP 客户端拉取 K 线/行情
- 修改 `services/strategy-engine/app/routers/strategy.py` 的 `run_strategy`：调用 `data_client` 而非 TODO 注释
- requirements.txt 增加 httpx

**b) trading-service 接入 risk-service**：
- 修改 `services/trading-service/app/engine.py` 的 `submit_order`：下单前调用 `http://risk-service:8005/risk/check` 进行风控检查
- 风控失败时拒绝订单（设置 `reject_reason`）

**c) trading-service 接入 portfolio-service**：
- 成交后调用 `http://portfolio-service:8004/portfolio/update` 回填持仓

**d) backtest-service 接入 strategy-engine**：
- 回测前调用 `http://strategy-engine:8001/api/v1/strategy/{id}` 拉策略参数（已有 strategy_id 字段）

## 假设与决策

1. **默认 mock 模式**：所有数据流默认走 mock provider，配置 TUSHARE_TOKEN 后自动切换 tushare。无需用户提供真实凭据即可演示完整功能。
2. **认证默认开启**：所有业务 API 加 `Depends(get_current_user)`，仅 `/auth/*`、`/health`、`/docs` 公开。
3. **不引入 Celery**：用 APScheduler 嵌入式调度，避免引入额外基础设施。如未来需要分布式任务再迁移。
4. **不引入消息中间件**：服务间通信用 httpx 同步调用 + Redis pubsub 推送。回测等长任务用 FastAPI BackgroundTasks。
5. **保留所有现有代码**：仅修改/扩展，不删除现有 engine.py 等已实现逻辑。
6. **前端用 ECharts**：已在 package.json，未使用 → 在新组件中启用。
7. **策略 ID 类型**：common/models/strategy.py 用 `Integer` 主键，strategy-engine 内部用 `str`，转换在 router 层完成。
